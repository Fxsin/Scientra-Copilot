# Summary Agent Mode

## Overview

Scientra Copilot supports two summary generation modes:

| Mode | Module | Default | Requires |
|------|--------|---------|----------|
| **agent** | `summary_agent.py` | ✅ Yes | `ANTHROPIC_API_KEY` (optional, works without it in Claude Code) |
| **direct_api** | `summary_engine.py` | No (legacy) | `DEEPSEEK_API_KEY` (required) |

## Agent Mode (Default)

Agent Mode generates summaries via the configured LLM agent. When running inside Claude Code, summaries are generated by Claude Code Agent using the current model configuration — no external API key required.

### How It Works

```
Scientra Copilot → Agent SDK → Claude Code Agent → summary.md
```

1. Paper metadata, raw text, and tags are collected
2. A structured prompt is built (same format as direct_api mode)
3. If an API key is available (`ANTHROPIC_API_KEY` or `DEEPSEEK_API_KEY`), the LLM is called directly
4. If NO API key is available, the prompt is written to `03_Summary/agent_prompts/<paper_id>/prompt.json` with status `pending_agent`
5. Pending prompts are resolved by the Claude Code Agent session

### API Key Resolution Order

```
ANTHROPIC_API_KEY → DEEPSEEK_API_KEY → SCIENTRA_API_KEY
```

### Running in Claude Code (No API Key)

When running inside Claude Code without an explicit API key:
- Summaries are NOT blocked — the system writes prompt files
- The Claude Code session picks up `pending_agent` prompts
- Summaries are generated using the current model (e.g., deepseek-v4-pro, claude-sonnet-4-6)
- Output format is identical to direct_api mode

### CLI Usage

```bash
# Summarize all papers (agent mode)
python -m scientra.summary_agent --all --root g:/AI_agent/Scientra Copilot

# Summarize a single paper
python -m scientra.summary_agent --paper-id paper_2247e647bb604df2

# Force regenerate, write prompts only (no API call)
python -m scientra.summary_agent --all --force --prompt-only

# With explicit API key
python -m scientra.summary_agent --all --api-key $ANTHROPIC_API_KEY
```

### Output Format

Agent Mode produces the same structured `summary.md` as direct_api mode:

- **Core Finding** — one-sentence core discovery
- **Evidence** — supporting evidence with source citations
- **Methods** — experimental methods used
- **Key Results** — quantitative and qualitative results
- **Limitations** — acknowledged limitations
- **Relevance to My Research** — relevance to toxin/receptor/mechanism research
- **Citation Anchors** — source ID mapping table

## Direct API Mode (Legacy)

Direct API Mode calls the DeepSeek API directly using raw HTTP requests. This mode is preserved for backward compatibility and environments where direct API access is preferred.

### Configuration

```yaml
# Config/workflow_config.yaml
steps:
  summary:
    mode: "direct_api"       # Switch to legacy mode
    fallback_mode: "agent"   # Fallback if direct_api fails
```

### Requirements

- `DEEPSEEK_API_KEY` environment variable (required)
- Network access to `https://api.deepseek.com`

---

## Switching Modes

### Via Config File

Edit `Config/workflow_config.yaml`:

```yaml
steps:
  summary:
    mode: "agent"        # or "direct_api"
    fallback_mode: "direct_api"  # or "agent"
```

### Via Workflow Runner

The workflow runner automatically reads `summary.mode` from config:

```bash
# Uses mode from workflow_config.yaml (agent by default)
python workflow.py run --input-dir 00_Inbox/batch_30 --force --from-step summary
```

### Via system_check

```bash
# Auto-detects mode from config
python -m Scripts.system_check

# Explicit mode
python -c "from Scripts.system_check import run_system_check; run_system_check(summary_mode='agent')"
```

## Trade-offs

### Agent Mode

| Pros | Cons |
|------|------|
| No external API key required in Claude Code | Prompt-only mode requires manual resolution |
| Uses current model configuration | Slightly different API format per provider |
| Unified with Agent SDK architecture | Requires Claude Code for zero-key operation |
| Survives API key rotation | |

### Direct API Mode

| Pros | Cons |
|------|------|
| Direct, low-level HTTP control | Requires DEEPSEEK_API_KEY |
| Proven, stable implementation | Tied to DeepSeek API specifically |
| Independent of Claude Code | Blocked without API key |

---

## Migration from direct_api to agent

1. Update `Config/workflow_config.yaml`: set `summary.mode: "agent"`
2. No code changes needed — the workflow runner routes automatically
3. Set `ANTHROPIC_API_KEY` (or keep `DEEPSEEK_API_KEY` as fallback)
4. Run `system_check.py` to verify the new mode
5. Existing `summary.md` files and caches remain compatible

To revert: set `summary.mode: "direct_api"` and ensure `DEEPSEEK_API_KEY` is set.
