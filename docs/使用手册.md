# Scientra Copilot 使用手册

> **版本:** v1.4 — Evidence-Oriented Literature Agent Chat + Supplementary Data Pipeline

## 快速开始

### 1. 环境要求
- Python 3.11+
- Docker（用于 GROBID PDF 解析）
- Node.js 18+（用于 Web 前端）

### 2. 启动服务

```bash
# 一键启动（API + Web）
python Scripts/dev_restart.py

# 或分别启动：
python -m scientra.server          # API: http://127.0.0.1:8710
cd web && npm run dev              # Web: http://127.0.0.1:3000
```

### 3. 导入文献

```bash
# 将 PDF 放入 00_Inbox/
python workflow.py run
```

### 4. 配置 LLM API（推荐，用于 AI 对话）

```bash
python Scripts/setup_llm.py
```

选择 DeepSeek 或 Anthropic，粘贴 API key 即可。Key 保存在 `Config/llm_config.yaml`（不会上传到 git）。

### 5. 构建补充数据资产（可选）

```bash
# 导入手动下载的补充文件
python -m scientra.pdf_data_assets.build_assets --import-supplementary

# 构建补充链接
python -m scientra.pdf_data_assets.build_assets --supplementary --all --force

# 索引补充实体
python -m scientra.pdf_data_assets.build_assets --supplementary-entities --all --force

# 质量检查 + 重新嵌入
python -m scientra.pdf_data_assets.build_assets --quality-check
python -m scientra.pdf_data_assets.asset_embedding --all --force
```

## 核心功能

### 💬 AI 文献对话（v1.0-alpha → v1.4）

访问 `http://127.0.0.1:3000/chat`，直接对文献库提问。

**七类核心查询，系统自动识别意图：**

| 查询类型 | 示例问题 | 输出格式 |
|---|---|---|
| **claim_query** | What claims need stronger evidence? | 结构化 Claim → Evidence → Missing evidence → Sources |
| **research_gap_query** | What research gaps can be inferred? | Evidence-based gaps + Inferred gaps |
| **method_query** | What methods are commonly used? | 按类别分组（分子/蛋白/生测/显微/计算） |
| **result_query** | Which results are most frequently reported? | 结果分类 + 证据强度评估 |
| **supplementary_entity_query** | Is MAP2K4 present in supplementary tables? | 实体定位 + 数值 + 来源 |
| **supplementary_entity_comparison_query** | Compare MAP2K4 across supplementary data. | 跨论文聚合 + 方向汇总 |
| **hybrid_search** | 通用文献问题 | 混合检索 + LLM 综合 |

**三种回答模式：**
| 模式 | 说明 |
|---|---|
| Auto（推荐，默认） | 有 API key 时用 LLM 生成综合回答；否则展示检索证据 |
| LLM synthesis | 强制使用 LLM API 生成学术化引用回答 |
| Evidence-only | 不调用 LLM，直接展示结构化检索证据 |

**安全特性：**
- 自动过滤出版商免责声明、版权声明、数据可用性声明
- 杜绝 `[object Object]` 等代码污染
- 所有回答必须带 `[Ref:N]` 可追溯引用
- API key 绝不暴露到前端

**论文页面提问：** 在 `/paper/{id}` 页面，展开 "Ask this paper" 卡片，可直接对当前论文提问。

### 📋 补充数据查询（Phase 2 新增）

系统支持对论文补充表格（Supplementary Tables）中的实体（基因、蛋白质、化合物等）进行精确定位查询。

**实体查询示例：**
```
Chat: "Is MAP2K4 present in supplementary tables?"
Chat: "What are the FC and p-value for CASP3?"
Chat: "What does TRAF4 show in supplementary data?"
Chat: "Compare MAP2K4 across supplementary data."
```

**查询结果包含：**
- 实体所在论文和补充表格标签
- 数值列（FC, p-value, log2FC, Expression 等）
- 关联的补充表格引用
- source_link_count（同一数据行被多个标签引用的次数）

**LLM 解释模式（use_llm=true）：**
- 保守的数据解释（不推断因果机制）
- 明确列出 "What this does not prove"
- source_link_count 不被当作独立证据
- 跨论文比较时明确标注 "not a true cross-paper comparison"

## 补充数据处理（Phase 2 完整流程）

### 1. 手动导入补充文件

将下载好的 xlsx/csv/tsv 补充数据文件放入 `00_Supplementary/inbox/`：

```bash
00_Supplementary/inbox/
├── {paper_id}__Table_S1.xlsx      # 高置信匹配
├── {paper_id}__Supplementary_Data_1.csv
└── {label_only}__Table_S2.csv     # candidate_only（需改名确认）
```

推荐命名格式：`{paper_id}__{supplement_label}.{ext}`

### 2. 扫描并匹配

```bash
# 扫描 inbox
python -m scientra.pdf_data_assets.build_assets --import-supplementary

# 匹配到论文引用
python -m scientra.pdf_data_assets.build_assets --supplementary --all --force
```

### 3. 实体索引

```bash
python -m scientra.pdf_data_assets.build_assets --supplementary-entities --all --force
```

### 4. 质量检查和嵌入

```bash
python -m scientra.pdf_data_assets.build_assets --quality-check
python -m scientra.pdf_data_assets.asset_embedding --all --force
```

## API 接口

| 接口 | 说明 |
|---|---|
| `GET /health` | API + LanceDB 状态 |
| `GET /papers` | 分页论文列表 |
| `POST /query/assets` | 搜索资产片段（11 种 chunk type） |
| `POST /query/evidence` | 搜索证据片段 |
| `POST /query/supplementary-entities` | 搜索补充实体 |
| `POST /query/supplementary-entity-comparison` | 跨论文实体比较 |
| `POST /v1/agent/ask` | AI 文献问答 |

### SDK 使用

```python
from scientra.sdk import (
    query_assets,
    query_supplementary_entities,
    query_supplementary_entity_comparison,
    ask_literature,
)

# 搜索补充实体
results = query_supplementary_entities("MAP2K4", entity_type="gene")

# 跨论文比较
comparison = query_supplementary_entity_comparison("MAP2K4")

# 文献问答
answer = ask_literature("What does CASP3 show in supplementary data?", use_llm=False)
```

## 数据资产化流程

```
PDF → GROBID 解析 → 元数据 → AI 摘要 → 证据提取 → 数据资产化 → 向量嵌入 → 智能检索
```

**数据资产化层包含（Phase 0–2G）：**
- 章节文本（sections）
- 方法（methods）
- 结果（results）
- 实体（entities：蛋白质、基因、物种等 16 种）
- 论断（claims）
- 证据链接（evidence links）
- 图表（figures：标题、类型、引用句）
- 表格（tables：标题、类型、结构状态）
- 补充链接（supplementary links：引用识别、文件匹配）
- 补充实体（supplementary entities：基因/蛋白/化合物索引）
- 实体比较（cross-paper comparison）
- Agent 可调用的知识片段（11 种 chunk type）

## LLM API 配置详解

### 支持的 LLM 提供商

| 提供商 | 模型 | 获取 Key |
|---|---|---|
| DeepSeek | deepseek-chat | https://platform.deepseek.com |
| Anthropic | claude-sonnet-4-6 | https://console.anthropic.com |

### 配置方式

**方式一：交互式设置（推荐）**
```bash
python Scripts/setup_llm.py
```

**方式二：环境变量**
```powershell
# Windows PowerShell
$env:DEEPSEEK_API_KEY = "sk-..."
setx DEEPSEEK_API_KEY "sk-..."
```

```bash
# Linux / macOS
export DEEPSEEK_API_KEY="sk-..."
```

### 安全说明

- API key 只保存在后端，**绝不会**暴露到前端
- `Config/llm_config.yaml` 已加入 `.gitignore`
- 不要在 `NEXT_PUBLIC_*` 环境变量中存储 key

## 常见问题

**Q: Chat 显示 "LLM API is not configured"？**
A: 运行 `python Scripts/setup_llm.py` 配置 API key，然后重启后端。

**Q: 如何切换到 Evidence-only 模式？**
A: 在 Chat 页面点击 Advanced Options → Answer Mode → 选择 Evidence-only。

**Q: API key 会被上传到 GitHub 吗？**
A: 不会。`Config/llm_config.yaml` 已加入 `.gitignore`。

**Q: 支持哪些文献格式？**
A: 目前支持 PDF 格式，通过 GROBID 解析。

**Q: 如何查询补充表格中的基因？**
A: 在 Chat 中直接提问 "Is MAP2K4 present in supplementary tables?"。系统会自动识别为 supplementary_entity_query。

**Q: 补充表格文件放哪里？**
A: 放入 `00_Supplementary/inbox/`，然后运行 `--import-supplementary`。

**Q: 为什么 source_link_count > 1？**
A: 同一个导入的数据行被多个补充表格标签引用（例如 Table S1, S2, S3 都引用同一数据行）。这不算独立证据。
